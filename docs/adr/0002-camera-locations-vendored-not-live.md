# Vendor Camera pin locations as a static snapshot, not a live fetch

Every other data source in this app (Sensor report, Event report, Citizen
report) is fetched live on every page load — deliberately, per `PRODUCT.md`'s
"never show stale data as fresh" principle, since a passability claim that's
even a few hours old can mislead a driver. Camera pins are different: BMA's
`bma-cctv` open-data CSV lists camera *positions*, which almost never change,
not a time-sensitive claim about current flood conditions. Fetching it live on
every load would add a fourth runtime dependency (another CKAN API that can
fail, rate-limit, or go down) for data that isn't actually time-sensitive, so
this app instead vendors a static JSON snapshot in the repo, regenerated by a
manually-run dev script (`scripts/update-cameras.mjs`) when someone notices
stale/missing cameras. A future reader seeing this as the one source that
*isn't* fetched live should not "fix" it to match the others — that would
reintroduce a real failure mode to solve a staleness risk that doesn't apply
here (a stale camera pin means "this camera moved or was decommissioned,"
not "this flood report might not be real anymore").
